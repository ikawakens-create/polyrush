# ADR-0007: Claude セッションのリポジトリ状態取り違え事故の防止

## Status
Accepted (2026-05-22)

## Context

2026-05-22 の Task 3 (PuzzleGenerator) 実装で、Claude Code Web の新規セッションが
develop ブランチを fetch していない状態で作業を開始した。

結果として:

- develop にマージ済みの Task 1 (polyomino.dart) と Task 2 (polyomino_transformer.dart) を
  「存在しないファイル」と判断
- 過去にレビュー・合意した API 設計を破棄し、独自の設計でゼロから再実装
- PolyominoTransformer クラスを廃して `normalizeCells` 等のトップレベル関数に変更
- `claude/implement-xxx-XXXXX` という自動命名ブランチを作成、develop から派生していない
- 結果として PR をそのままマージすれば Task 1/2 の確定資産が消失するリスクがあった

事故は事前のレビューで発見され実害は出なかったが、
**「Claude セッションは状態を持たない」「異なるセッション間で状態継承漏れが発生し得る」**
という運用上の弱点が顕在化した。

## Decision

セッションが変わっても同じ事故が起きないよう、以下の三層防衛を導入する。

### 第1層: CLAUDE.md (ガードレール)

リポジトリルートに `CLAUDE.md` を配置し、Claude が読み込んだ瞬間に
「作業開始時の環境チェック」を実行するよう指示する。

CLAUDE.md は Claude Code が自動で読み込む慣習があるため、
セッション開始時の状態誤認を最も早期に検知できる。

### 第2層: 指示書テンプレート (ベルト)

Opus が Code Web に渡すタスク指示書の冒頭に
「ステップ0: 環境チェック」セクションを必須化する。

これにより、CLAUDE.md が読み込まれなかったケース(別 AI ツール経由など)でも、
タスク単位で環境チェックが強制される。

### 第3層: 既存ファイル保護 (サスペンダー)

develop にマージ済みのファイルパスを CLAUDE.md に明示列挙し、
新規タスクでの変更を禁止する。違反時はユーザーへの確認を必須化する。

## Consequences

### ポジティブ

- セッション間の状態継承漏れによる事故を構造的に防止
- 新しい AI ツール (Cursor, Aider 等) が将来参入しても同じガードレールが効く
- 「なぜこのルールがあるか」が ADR として残り、半年後の自分が理解できる
- 人間の注意力に頼らない仕組み (ガードレール思想) をプロジェクト全体に拡張する素地ができる

### ネガティブ

- 単純なタスクでも環境チェックの数行が必要になる (数秒のコスト)
- CLAUDE.md と指示書の両方を更新する手間
- CLAUDE.md が古くなると逆効果なので定期的な見直しが必要

### モニタリング

以下のいずれかが発生したら、本 ADR の有効性を再評価する:

- CLAUDE.md があるにもかかわらず同種の事故が再発した場合
- CLAUDE.md のルールが多すぎて読まれなくなった場合(肥大化)
- 新しいセッション形態 (例: 別の AI ツール) で CLAUDE.md が読まれないケース
