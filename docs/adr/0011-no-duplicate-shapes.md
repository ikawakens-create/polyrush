# ADR-0011: 同一 source 形状の重複配置を禁止する（生成段階での dedup）

## Status

Accepted (2026-06-06)

## Context

### 解決したい問題

同じ source 形状のピースが 1 パズルに 2 個以上出ると、プレイヤーには
区別がつかず、パズルが自明になりやすい。1 パズル内で同じ形を二度使わない
ようにする。

### これまでの方針との違い

ADR-0008 / 0009 / 0010 は、construct の外側に検証層を「被せる」B 案で
確定資産を守ってきた。本件は事情が異なり、被せる方式を採らなかった。

理由は 2 つある。

(1) 重複回避は「出来上がった枠を後から弾くフィルタ」ではなく、
    「ピースを選ぶ瞬間の生成ルール」である。フィルタ層を被せる方式だと、
    重複なし配置が可能なのに運悪く重複を引き続け、リトライ上限超過で
    Err になる穴が残る。生成段階で使用済み形を候補から外せば、重複は
    構造的にゼロにできる。

(2) 対象の compact_puzzle_generator.dart は PR #50 でマージ済みの本番
    経路だが、その時点ではまだ CLAUDE.md の変更禁止リストに登録されて
    いなかった（宿題4が未了）。したがって確定資産として固定される前の
    最後の窓を使い、生成ロジック本体に dedup を直接組み込んだ。

### 現状の部品

- CompactPuzzleGenerator.generate({difficulty, seed}) が本番経路（ADR-0010）。
  listPlacementCandidates / countSolutions / isFrameSimplyConnected を
  組み合わせ、生成・解数検証・穴検証を自前で行う。
- difficulty.dart の pool は確定資産（変更禁止）。重複回避は pool を
  広げずに成立する必要がある。
- 座標系は (y, x) = (row, col)（ADR-0006）。

## Decision

### 判断 1: 重複回避は生成段階で行う（フィルタ層を新設しない）

compact_puzzle_generator.dart の _buildCompactFrame 内で、配置済み
source の id を Set で追跡し、次の候補選択時に使用済み source を候補から
除外する。向き・回転・反転が違っても source の id が同じなら同一形として
除外する。これにより 1 パズル内で同じ形は構造的に二度使われない。
接触辺数の最大優先選択（ADR-0010 判断 2）は、絞り込んだ候補の中で
そのまま効く。

### 判断 2: 例外として確定資産を直接編集した

ADR-0008 / 0009 / 0010 の「被せる」方式と異なり、今回は対象ファイルを
直接編集した。理由は Context (1)(2) のとおり。

重要: これは「今後は確定資産を自由に編集してよい」という方針転換では
ない。compact_puzzle_generator.dart が禁止リスト未登録だった一度きりの
窓を使ったものである。本 ADR と同じ docs 変更で同ファイルを禁止リストに
登録し、以後は従来どおり ADR-0007 / CLAUDE.md のガードレールに従う。

### 判断 3: フォールバック・設定フラグは持たない

常時 ON とする。ある手で候補が 0 になった場合は、新しい制御フローを
発明せず、既存のリトライ経路（placed=false → return null →
maxCompactRetries=8）に乗せる。

### 判断 4: 実現可能性は pool 構成で担保

- easy: 7 種（kTrominoes 2 + kTetrominoes 5）/ 3 個必要 → distinct 可能
- normal: 17 種 / 4 個必要 → 余裕あり
- hard: 17 種 / 5 個必要 → 余裕あり

実測（PR #52）: seed=1..500 × 3 難易度で
(A) パズル内に source.id の重複ゼロ、
(B) generate がすべて Ok（CompactPuzzleError を返さない）
を CI で確認済み。

## Consequences

### ポジティブ

- 同形重複が構造的にゼロになり、自明パズルが減る。
- フィルタ層を被せないため、重複起因の Err 連発リスクがない。層も増えず、
  ADR-0010 が懸念した保守性低下を避けられた。
- 充填率は非退行（既存テスト pass）。

### ネガティブ

- 確定資産を直接編集する前例を作った。将来の読み手が誤って
  「確定資産は編集してよい」と一般化するリスクがある。
  → 対処: 判断 2 に「一度きりの窓」と明記し、同じ docs 変更で
    禁止リストへ登録して窓を閉じる。

### 中立・申し送り

- 「長い棒の自明配置」「風車状の自明配置」などの非自明性は本 ADR の
  対象外（同形重複とは別軸）。将来 ADR-0012 候補として別途検討する。
- listPlacementCandidates は @visibleForTesting のまま本番から呼ばれて
  おり（PR #50 の技術的負債、ignore で警告抑制）、正式公開への格上げは
  確定資産変更を伴うため別タスクとして保留する。
- 仕様書 § 4.3.4（seed 文字列）と実装（seed int）の不整合（Issue #31）は
  ステージ2 の課題として引き続き保留。
