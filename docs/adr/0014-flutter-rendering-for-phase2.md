# 0014 Phase 2 のプレイ描画は Flutter 標準で実装する

- Status: Accepted
- Date: 2026-06-07

## Context

Phase 2 のプレイ画面の描画方式を決定する必要がある。
ADR-0001 はゲームエンジンとして Flame を採用する方針を記録しているが、
現状の board_preview は CustomPaint で実装されており、また lib/game/board/grid_geometry.dart
も Flutter 標準の描画基盤として確立している。

本ゲームのピース操作は「指で触れた時だけ動く」型であり、60fps の常時ループを必要とする
場面が薄い。最優先事項は指への即反応（体感遅延の最小化）であり、次いで初心者の保守容易性
と既存資産（grid_geometry、board_painter）の再利用性である。

## Decision

1. Phase 2 のプレイ描画は Flutter 標準（CustomPaint + ポインタイベント）で実装し、
   Flame は使わない。ドラッグ追従はアニメーションコントローラを挟まず、ポインタ座標を
   State に入れて即再描画することで体感遅延を最小化する。

2. 吸着先計算・配置可否・完成判定などのロジックは純粋 Dart 関数として実装し、
   UI（Flutter）を import しない。CIでテスト可能にする。
   完成の定義: 枠の全マスがピースで埋まった状態。

3. 手触りに関わる数値定数（指オフセット・掴み判定拡張・拾い上げスケール等）は
   FeelConfig クラスに 1 か所にまとめ、後から 1 か所で調整できるようにする。
   新しい抽象インターフェース（スキン等）は作らない。

4. 将来あるテーマが常時アニメや大量スプライトを必要とする場合に限り、Flame 採用を
   再検討する。その際、書き直すのは描画・入力層のみで、純粋ロジックとテストは流用できる。

## Consequences

### 利点

- 低遅延: ポインタ座標を State に直接反映するため、描画パイプライン外の遅延がない
- 既存資産の再利用: grid_geometry.dart・board_painter.dart の知見を流用できる
- 初心者が追える: Flutter 標準ウィジェットのみで完結し、Flame 固有の概念が不要
- 将来のエンジン乗り換えが低コスト: 純粋ロジック層と描画層が分離されているため

### 欠点

- 凝った常時アニメ（粒子エフェクト等）は AnimationController の手配線が必要になる

### ADR-0001 との関係

本判断は gameplay 層についての ADR-0001 からの意図的逸脱である。
ADR-0001 は当初スタック方針の記録として残す。
