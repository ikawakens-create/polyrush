# ADR-0016: セッション間の文脈引き継ぎを handoff ファイルで行う

- Status: Accepted
- Date: 2026-06-11

## Context

Code Web のセッションは状態を持たない(ADR-0007)。これまで前セッションの
成果・文脈は、完了報告をユーザーが手動コピペで運ぶことで引き継いでいた。
この方式はユーザーの往復負担と API 消費の両方を増やしていた。

## Decision

1. タスク完了時、Code Web は完了報告を docs/handoff/LATEST.md に
   上書き保存し、同じ PR に含めてコミットする(一セッション=一PR は維持)。
2. ファイルは常に docs/handoff/LATEST.md の 1 つだけとする。
   過去の handoff の履歴は git のコミット履歴で参照できるため、
   ファイルを溜めない。削除タスクも発生しない。
3. 内容は CLAUDE.md の「タスク完了時の報告フォーマット」6項目に加え、
   「次セッションへの申し送り」を含める。
4. 変更したコードの全文は handoff に含めない。コードの正本はリポジトリ
   本体であり、次セッションは git で直接読めるため。重複させると
   肥大化と陳腐化を招く。
5. 新しいタスクの開始時、Code Web は環境チェックの後に
   docs/handoff/LATEST.md を読み、直近の文脈を把握してから着手する。

## Consequences

### ポジティブ
- 次セッションへの文脈説明コピペが不要になり、ユーザーの往復が減る
- Opus へのレビュー受け渡しも LATEST.md 1 回のコピーで済む
- パスが固定なので、指示文・ブックマーク・確認手順がすべて単純になる
- ファイルが増えず、掃除タスクが発生しない

### ネガティブ
- 書き忘れ・読み忘れで仕組みが機能停止するリスク
  → CLAUDE.md にルール化し、ユーザーがマージ前確認に
    「LATEST.md の更新有無」を加えて防ぐ
- 並行セッションでは上書き競合する
  → 一セッション=一PR の直列運用では実質発生しない
