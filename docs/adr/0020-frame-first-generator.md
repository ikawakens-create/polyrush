# ADR-0020: 枠ファースト生成器 (FrameFirstPuzzleGenerator) の導入

- Status: **Accepted**(Opus 起草 2026-07-05 / Fable 確定 2026-07-05)
- 前提: ロードマップ ④「枠ファースト計測CI」(PR #96) の結果を受け、Fable が ⑤ を Go 判定。
- 根拠データ: docs/handoff/LATEST.md の計測レポート(重複ピース除去後の最新値)。
- Fable 確定サマリ: 判断2=A案(配置返しは新モジュール)＋条件(a)(b)、判断6=併用(easy 下限0.75)、
  判断7=幾何プレフィルタ不採用(YAGNI)、その他は草案どおり承認。詳細は各判断に反映済み。

---

## Context

### 解決したい問題

現行の生成は「ピース先行の逆構築」(NonTrivialPuzzleGenerator → CompactPuzzleGeneratorV3、
ADR-0018/0013)。ピースを貪欲に積んだ結果が枠になる方式のため、次の既知問題がある:

- easy seed=2 のような極端な細長枠が出る。
- normal で同一パズルが複数シードから出る(低バリエーション)。
- 「1つの枠を複数のピースセットで解ける」という実物ウボンゴの核(1枠→複数セット)が作れない。

HANDOFF_ROADMAP_solo_v1 §2-2 の方針に従い、生成を逆転する:
**「良い枠を先に生成 → その枠を敷き詰め可能なピースセットをソルバで列挙 → 採点して採用」**。

### ④ 計測結果(実現可能性の裏づけ / PR #96・重複ピース除去後)

| 難易度 | 制約充足(h,w,n) | 候補セット/枠 | 敷詰め可能/枠 | 探索時間/枠(平均) | 解数1〜3割合 |
|---|---|---|---|---|---|
| easy | (3,4,11) の1択 | 20 | 14.0 | 15ms | 85.7% |
| normal | (4,5,17/18/19) | 816 | 205.8 | 436ms | 82.3% |
| hard | (4,6,21/22)(5,5,22/23) | 660 | 335.7 | 1071ms | 51.5% |

判定に効く含意:

- **総当たり(candidateSet × countSolutions)は全難易度で打ち切り0で完走**(時間予算12000ms
  に対し hard でも最大1315ms)。枠ファーストは計算量的に実用可能。
- **1枠から採用可能セットが大量に取れる**(easy ~12・normal ~170・hard ~170 相当)。
  「1枠→複数セット」(⑥マルチセット化)の前提が強く裏づけられた。
- **easy の枠バリエーションが構造的に狭い**: 充填率85〜95%×アスペクト≤1.6×セル数9〜12 を
  同時に満たす外接矩形は (3,4) の1択のみで、生成される枠形状は実質4種。→ 判断6 で対処。
- 解数1〜3割合は難易度が上がるほど低下(hard で51.5%)。hard ほど「解数4以上に頭打ちする
  セット」が相対的に多い＝採用選別が要る。

### 現状の部品(いずれも CLAUDE.md により変更禁止)

- `PuzzleSolver.countSolutions({frame, shapes, limit})` — 枠への敷き詰め**解数のみ**を返す
  (最大 limit で頭打ち)。**具体的な配置(tiling)は返さない。**
- `CompactPuzzleGeneratorV3.generate`(ADR-0013)— 逆構築の本番生成器。maxCompactRetries=16、
  `usedSourceIds`(`source.id` の Set)で1タスク内ピース重複を禁止、フォールバックなし
  (`isFallback` 常に false)、`(seed, attempt)` から決定論的サブシード派生。
- `NonTrivialPuzzleGenerator.generate`(ADR-0018)— V3 のラッパー。normal/hard で
  straightCutSeparable==false を優先、なければ protrusionRatio 最小をフォールバック。
- `computePuzzleMetrics`(ADR-0017)— GeneratedPuzzle を読む純関数。straightCutSeparable /
  protrusionRatio / fillRatio ほか。
- `isFrameSimplyConnected`(ADR-0009)、ポリオミノ定義・回転変換(ADR-0006 座標系 (y,x))。

### 消費側のデータ契約

アプリ(`play_screen.dart`)は `NonTrivialPuzzleGenerator.generate()` を呼び、
`Result<VerifiedPuzzle, CompactPuzzleError>` を受け取る。`VerifiedPuzzle` は
`GeneratedPuzzle`(`Set<Cell> frame` と `List<PlacedBlock> blocks`)を保持し、
`PlacedBlock` は `{source, orientation, cells}` を持つ。**UI 層は完成品データ
(frame と各ピースの配置 cells)しか見ず、生成過程には非依存**(§2-2 の「衝突しない根拠」)。

### 参考実装

④(PR #96)の `test/unit/domain/puzzle/frame_first_feasibility_report_test.dart` 内の
枠生成ヘルパー(`_carveFrame` / `_validBoxNs` / `_enumerateSets`)が本 ADR の参考実装。
lib/ 配下には未配置(正式実装は本 ADR で行う)。

## Decision(草案 — 各判断は Fable の確定を要する)

### 判断1: 新ファイルとして追加し、V3 系は切替式で並存(B案・item 3 前半)

`lib/domain/puzzle/frame_first_puzzle_generator.dart` を**新規追加**。
V3・NonTrivial ラッパー・solver・metrics などの確定資産は一切変更しない(ADR-0008 以降の
B案を踏襲)。V3 は削除せず、切替式で並存させる。

- 切替点は本番の呼び出し口 `play_screen.dart`(2箇所)。生成器選択のトグルを設け、
  既定は当面 V3(NonTrivial) 経路のままとし、frame-first は明示的に有効化して実機評価する
  (段階的ロールアウト)。
- トグルは初期は**コンパイル時 const**(例 `kUseFrameFirstGenerator`)で安全に切替、
  実機評価後にランタイム設定へ昇格を検討。トグルの正確な機構は Fable/井川 の裁量。
- 公開 API シグネチャは V3/NonTrivial と揃える
  (`Result<VerifiedPuzzle, CompactPuzzleError> generate({required Difficulty, required int seed})`)。
  差し替えを局所化し、戻り値契約(VerifiedPuzzle)を維持する。

### 判断2: パイプライン構成(枠→セット→採用→配置の materialize)

1. **枠生成**: 判断3 の基準で枠(`Set<Cell>`)を1つ生成(決定論的)。
2. **候補セット列挙**: 難易度プールから重複なしで blockCount 個、セル数合計＝枠セル数の
   組み合わせを列挙(判断5)。
3. **採用判定**: 各候補に `countSolutions(frame, set, limit=4)` を実行。解数∈{1,2,3} を
   採用候補とする(既存の採用基準・ADR-0008 判断3)。normal/hard は判断7 の非自明性
   選好を適用。**決定論的順序で走査し、最初に条件を満たしたセットで確定**(全列挙は不要。
   よって実生成時間は ④ の網羅計測値より大幅に短い)。
4. **配置の materialize**: 採用セットを枠へ実際に敷いた **1解(tiling)** を求め、
   `List<PlacedBlock>`(各 source/orientation/cells)を構成して `GeneratedPuzzle` を組む。
   `solutionCount` は手順3の `countSolutions` の値、`isFallback` は false(判断8)。

`countSolutions` は**配置を返さない**ため、手順4 の「1解の materialize」には配置を返す部品が
別途必要。solver.dart は変更禁止。

**Fable 確定: (A) 新モジュール内に配置返しバックトラッカを新設。**
B案原則を ADR-0008/0013 の前例どおり適用し破壊リスクゼロを優先。新モジュールは countSolutions
より単純(最初の1解で early exit、数え上げ不要の「縮小版」)。副産物として、配置を返す部品は
将来のヒント機能(解を1つ提示)にそのまま転用できる。

確定に伴う条件(⑤ 実装で必須):

- **条件(a) 決定論**: 同じ枠＋セット＋seed なら常に同じ tiling を返す。実装指針: pivot＝最小空セル
  (y,x)、ピースは与えられたセット順、向きは正準キー昇順で走査。
- **条件(b) 整合性テスト**: 「`countSolutions ≥ 1` のセットに対し materialize が必ず1解を返し、
  その解が枠を過不足なく被覆する」ことを複数シードで検証するテストを ⑤ PR に含める。solver と
  新モジュールの探索が食い違えばここで検出する。(Opus 事前検証: 全難易度 17,810 セットで
  count≥1 ⇔ materialize 成功・被覆過不足なし・決定論 OK。実装後 Dart でも同テストを回す。)

### 判断3: 枠生成基準(④ の _carveFrame を lib/ へ正式実装)

枠は次を満たす(④参考実装を昇格):

- セル数 n は難易度の既存規定(easy 9〜12 / normal 16〜20 / hard 20〜25)。
- 充填率 = n / 外接矩形面積 ∈ [下限, 0.95](下限は判断6 で確定)。
- アスペクト比(外接矩形 長辺/短辺)≤ 1.6。
- 単一連結(4近傍)・穴なし・外接矩形の4辺すべてに接触(実 bbox が縮まない)。
- 充満矩形から縁のセルを彫って「ずんぐり型」に成形(凹み1〜3箇所相当)。
- 決定論的(seed から再現可能)。

### 判断4: 枠の正準形による重複排除(item 2)

枠形状を回転・反転不変の**正準形**で同一視し、同一形状の重複出題を排除する。

- 正準形キー = 枠セルに8つの二面体変換(回転4 × 反転2)を施し、各を (0,0) 正規化して
  row-major 文字列化した8個のうち**辞書順最小**。
- 生成側は正準形キーで重複を弾く(同一シード run 内／将来のデイリー配布での同一性判定に使用)。
- 副次効果: 正準形キーは「全員に同じ枠を配る」デイリーチャレンジ／タイムアタックの
  安定 ID として使える(判断10)。

(注: ④ 参考実装の `_canon` は平行移動正規化のみ。本 ADR の正準形は8変換の最小を取る点で強化。)

### 判断5: セット列挙は重複なし(usedSourceIds と同ルール・item 4)

候補セットは**全ピース異種**(1タスク内で同一 source を2回使わない)。V3 の `usedSourceIds`
(`source.id` の Set)と同じルールで、実物ウボンゴも1タスク内は全異種。

- 列挙は難易度プールからサイズ昇順ソート＋上下界枝刈りで、重複なし(`rec(i+1, ...)`)に
  セル数合計＝枠セル数の組み合わせのみを生成(④ の修正済み `_enumerateSets` と同一方針)。
- `countSolutions` はセル数不一致だと0を即返すため、合計一致に絞ることで無駄呼び出しを回避。

### 判断6: easy の枠バリエーション対策(item 1 / Fable が方向確定)

④ で easy の枠形状が実質4種と判明。二案を比較する。

**案 1a: easy のみ充填率下限を緩和(推奨寄り)**
充填率下限を 0.85 → 例 0.70 に下げると、easy の制約充足枠が
(3,4) N=9/10/11 ＋ (4,4) N=12 に拡大(試算)。枠形状の種類が大幅増。

- 長所: 枠形状そのものが多様化。実機で「毎回違う枠」を体感できる。アスペクト≤1.6 は維持。
- 短所: 充填率が下がると「ずんぐり感」が薄れ空きが増える(＝易しくなる方向で、easy には許容的)。
  下限値は実機の手触りで要調整。

**案 1b: 枠は現状のまま、バリエーションはマルチセット／向きで担保**
easy 枠は (3,4)/N=11 主体のまま、1枠から取れる多数の採用セット(④: 敷詰め可14/枠)と
③スクランブル(向きランダム化)で体感の多様性を出す。

- 長所: 充填率を高く保てる(ずんぐり感維持)。⑥マルチセット化と自然に連続。
- 短所: 枠の外形がほぼ同一(3×4から1セル欠け)で、外形の単調さは残る。

**Fable 確定: 1a と 1b を併用。easy のみ充填率下限を 0.85 → 0.75 に緩和し、あわせて
マルチセット／向きでも担保する。normal/hard の下限は 0.85 のまま(④で問題が出ていない)。**

下限 0.75 の根拠(Opus 検算済み): セル数帯が離散のため、下限を 0.70 に下げても 0.75 に
下げても解禁される (h,w,n) は同一で `(3,4,9)(3,4,10)(3,4,11)(4,4,12)`。0.76 では早くも
(3,4,9)(4,4,12) が脱落する。ゆえに **0.75 が同一効果を得られる最も高い下限**(ずんぐり感の
名目的保険)。効果の実測: easy の distinct 正準形状(8二面体変換で正規化・全彫り方を厳密列挙
した理論上限)は **3種(下限0.85)→ 154種(下限0.75)** に増加。

条件(⑤ 実装で必須): 計測テストに「easy・下限0.75 で N シード生成したときの **distinct 正準
形状数**(判断4 の正準形でカウント)」のレポートを含める(測ってから組み込む原則。実測が
理論上限154 に対しどこまで届くかを数字で確認し、実機評価の参考にする)。

### 判断7: ADR-0018 非自明性フィルタの意図引き継ぎ(item 3 後半)

ADR-0018 の separable 棄却＆protrusion 最小フォールバックの**意図を frame-first パイプラインに
引き継ぐ**。役割を「生成後のふるい」→「frame-first の採用選択条件」へ移行する(§2-2)。

- normal/hard: 判断2 手順3 で採用候補(解数1〜3)のうち、materialize したタイリングに
  `computePuzzleMetrics` を適用し、`straightCutSeparable == false` を優先採用。
  非自明が得られなければ protrusionRatio 最小の採用候補にフォールバック(ADR-0018 判断3/4 と同一挙動)。
- easy: ADR-0018 同様フィルタ対象外(そのまま採用)。
- separable は本来タイリング依存(ADR-0017)だが、frame-first では枠選択後にタイリングが
  決まるため、上記のとおり「採用タイリングに対する metrics 判定」で実装する。
- **枠幾何のみの separable 事前フィルタは Fable 確定で「今回は不採用」(YAGNI)**。理由:
  未計測の最適化であり、④実測では時間に十分余裕がある。判断9 の効果測定で「separable 棄却
  リトライが時間を食っている」と数字で出た場合にのみ再検討する。

### 判断8: 決定論・再生成・フォールバック方針は V3 を踏襲

- `(seed, attempt)` からの決定論的サブシード派生、リトライ上限(V3: maxCompactRetries=16 相当)、
  **フォールバックなし(`isFallback` 常に false)** を踏襲。
- 生成した枠が採用セットを1つも持たない稀ケースは、その枠を破棄して次サブシードへ
  (④ の実測では採用セットが枠あたり多数あり、破棄は稀の見込み)。
- 全リトライで枠が組めない/採用セットが得られない場合のみ `Err`
  (`CompactPuzzleError.generationFailed` / `qualityNotMet` を流用)。

### 判断9: 効果測定(測ってから組み込む・ADR-0010 判断5 踏襲)

正式実装後、V3(NonTrivial) と frame-first を並べて CI 計測する:
充填率・straightCutSeparable 率・生成成功率・**実生成時間(早期確定込み)**・
1枠あたり採用可能セット数。これらで実機投入前に非退行と実用性を確認する。

### 判断10: 将来機能の下地(デイリー／タイムアタック)

判断4 の正準形フレーム ID により「全員同じ枠」を安定配布できる。⑥マルチセット化・
⑦タイマーモードの前提(同一枠を複数人・複数セットで解く)を satisfy する。本 ADR 自体は
これらを実装しないが、設計をブロックしない位置づけ。

## Consequences(草案)

### ポジティブ

- 極端な枠形状・同一パズル問題を構造的に解消。1枠→複数セットのウボンゴ的体験が可能に。
- 確定資産(solver / V3 / metrics)不変。切替式のため失敗時は V3 経路へ即戻せる。
- ④ 計測で計算量の実用性を確認済み。早期確定により実生成は網羅計測より高速。
- 正準形フレーム ID がデイリー／タイムアタックの下地になる。

### ネガティブ

- 配置を返す部品(判断2-A)は solver の探索を一部複製する(死んだコード増)。
  → 対処: B案の許容範囲。将来の生成層一本化(ADR-0013 判断7)で棚卸し対象に含める。
- easy の充填率下限緩和(判断6-1a 採用時)は「ずんぐり感」とのトレードオフ。
  → 対処: 実機評価で下限値を調整。判断9 の計測で監視。
- 生成器が2系統(V3 と frame-first)並存し分岐が増える。
  → 対処: 切替トグルを単一箇所(play_screen)に集約。段階的ロールアウト後に一本化を検討。

### 中立・申し送り(Fable 確定済み)

- 判断2: (A) 新モジュールに配置返しバックトラッカ確定。条件(a)決定論・(b)整合性テストを ⑤ に必須。
- 判断6: 1a＋1b 併用確定。easy 下限 0.75、normal/hard 0.85 据え置き。distinct 正準形状レポートを ⑤ に必須。
- 判断7: 枠幾何の事前 separable フィルタは不採用(YAGNI・判断9 の結果次第で再検討)。
- 切替トグルはコンパイル時 const で開始(Fable 承認)。実機評価後に runtime 昇格を検討。
- ⑤ の実装分割(Opus 運用提案): ⑤a=新規 lib モジュール群＋テスト＋本 ADR、⑤b=生成器統合＋
  トグル＋効果測定(判断9)。各 PR は独立にグリーン。詳細は指示書側で管理。
